# Roaster — Project Scope

## Business Purpose

Roaster is an AI-powered code review tool. Developers paste code into an online editor, submit it, and receive an automated review generated by a local AI model. The review surfaces line-level comments with severity ratings and a summary. Developers can then reply to individual comment threads and receive follow-up AI responses, turning the review into a conversation.

The primary use case is solo or small-team development where getting fast, asynchronous feedback on code quality — without waiting on a human reviewer — adds value.

---

## Core User Workflow

1. **Create a session** — give it a name; each session represents one piece of work being reviewed.
2. **Write or paste code** — into the Monaco editor; select the language.
3. **Submit** — the code is queued for review; the user polls until the result is ready.
4. **Read the review** — a summary plus per-line comments, each with a severity level (Gentle / Medium / Brutal).
5. **Reply to comments** — start a thread on any line; the AI replies, forming a back-and-forth conversation.
6. **Resubmit** — update the code and resubmit; the old payload is preserved in history, the review is regenerated.

---

## Scope

### In Scope

- Session management (create, list, soft-delete, navigate to).
- Code submission and asynchronous AI review via a locally-run Ollama model (`qwen2.5-coder:7b`).
- Line-level review comments with severity classification.
- Threaded replies per review comment line, with full conversation history sent to the AI on each reply.
- Submission history — every resubmit auto-archives the previous code payload.
- Audit event log per submission (Submitted → ProcessingStarted → ReviewCompleted / Failed → UserReplied → AiReplied).
- Review performance metrics captured per submission (model ID, timing, token counts).

### Out of Scope (as of current state)

- User authentication and multi-tenancy — there are no user accounts; all sessions are shared.
- Real-time push notifications — the frontend polls the review endpoint.
- Support for languages beyond C#, JavaScript, TypeScript, and JSON (editor UI constraint, not a backend constraint).
- Pull request or VCS integration — code is pasted manually, not pulled from a repository.
- Cloud-hosted AI — the system is designed around a locally-run Ollama instance.

## Technology Summary

| Layer | Stack |
|---|---|
| Frontend | Blazor WebAssembly (.NET 10), MudBlazor 9.4, BlazorMonaco 3.4 |
| API | ASP.NET Core 10 Minimal APIs |
| Background workers | MassTransit 8 + RabbitMQ |
| AI integration | Semantic Kernel 1.74.0 + Ollama (`qwen2.5-coder:7b`) |
| Database | PostgreSQL 17 via EF Core 10 + Npgsql |
| Migrations | DbUp 7 |
| Tests | xUnit, Moq, FluentAssertions |
| Local stack | Docker Compose (Postgres, RabbitMQ, Ollama, API, Consumer, Frontend) |
